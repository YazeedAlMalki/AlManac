# Code audit — 2026-10-19

Scope: everything in the repository: `Sources/AlmanacCore`, `Native/` (app and
widget), `Tests/`, `tools/` (Python), CI, and agent and tooling config. The
fixes are on branch `claude/code-audit-fixes`.

This container has no Swift toolchain. The Swift changes were checked by
reading them, and CI (`swift build && swift test`, `xcodebuild`) is what
compiles and tests them. The Python tool suites were run here and pass.

## Backdoor / loophole sweep: nothing malicious found

- The app makes **no network calls**: no `URLSession` and no URLs outside
  attribution text. Nothing sends data off the device.
- Test seed hooks (`VitalsSeedPlan`, `KitchenSeedPlan`, the
  `-AlmanacRunLogWaterIntent` argument and others) only run when a launch
  argument names them, and their only call sites are inside `#if DEBUG`.
  A Release build cannot reach them.
- No credentials or private keys in the tree or in git history.
- `.opencode/` skills, `opencode.json` and `.xcodebuildmcp/` hold no hidden
  instructions. The one MCP package they run is pinned (`xcodebuildmcp@2.7.0`).
- All SQL that builds strings by interpolation uses only table or column
  names written in the code. Every value goes in as a bound parameter.

## Security and robustness fixes

| Where | Problem | Fix |
|---|---|---|
| `BackupZipper.unzip` | `cdOffset + cdSize` was added as `UInt32`. A crafted zip could overflow it and crash the app. | The sum is now 64-bit and the archive is refused. |
| `BackupZipper.unzip` | The doc said "exactly one" backup entry, but the code took the last one. | An archive with more than one backup entry is refused. Only the entry's final file name is used. |
| `restoreBundle` | Trusted `bundle_meta.schema_version`, which the bundle states about itself. Did not check the payload database's integrity or its triggers. | Checks the payload's own migration head, runs `PRAGMA quick_check`, and refuses triggers or views the app does not define. New tests cover both checks. |
| `BackupService.restore(from:)` | Public restore with no checks at all. | Made `internal`. Only tests use it. |
| `BackupView.importBackup` | Did not call `startAccessingSecurityScopedResource`, so files picked from Files or iCloud could not be read. Opened the user's original file read-write to validate it. | Requests access, copies the file into a private temp folder, validates the copy and adopts that copy. |
| `MigrationRunner` | The app and the widget can both migrate after an update. The second one would run the same migration again and fail. | Checks again whether the version is applied, inside the transaction lock. |
| `HealthKitProvider.storedIdentifier` | Searched every app's samples for the sync identifier. | Searches only this app's own samples. |

## Bugs fixed

- **Reminders were rescheduled on every pass.** `NotificationScheduler.matches`
  compared the pending trigger's original interval with the planned interval
  measured from now, which gets shorter as time passes. They stopped matching
  after the first pass, so every reconcile removed and re-added every reminder.
  It now compares fire dates.
- **Step counts of 10,000 or more were grouped wrongly** (`HealthView`).
  12345 showed as "1,2,345" because of the regex. Fixed.
- **"nan", "inf" and hex were accepted as numbers.** `Double(userInput:)` and the
  lab CSV importer accepted them, so a lab value of "NaN" or "0x10" could be
  stored as a number. Both now accept plain decimal numbers only. Tests added.
- **Error messages showed a literal `\(relativePath)`.** Two backup error
  strings had an escaped backslash, so the path was never filled in.
- **SHA-256 was quadratic.** `removeFirst(64)` ran once per block on a 1 MiB
  buffer, which made hashing backups very slow.
- **Timeline times ignored the 12/24-hour setting.** They were hard-coded to
  `HH:mm` with no display calendar. They now use `almanacFormatted`.

## Dead code removed

- `Documents/DocumentStore.swift`: nothing referenced it, not even tests. Its
  `read(relativePath:)` did not check paths.
- `LabImportJobStore.markFailed`: never called, and it wrote an empty
  `finished_at`. The doc that cited it is corrected.
- `HydrationCalculator.adaptProfile` (and its private helper),
  `HydrationLoggingService.logAmount`,
  `HydrationReminderService.reminderMessage` (English-only text),
  `FastingIntakeLog.earliestIntake`, `GoalTargetSnapshot.isManualTarget`,
  `TabCoordinator.isShowing`, `CircadianPresentation.shortLabel` and
  `isTransition`, and the `EdibleYield` enum (a duplicate of
  `EdibleProportion`).
- Unused Python imports in `tools/`.

## Inconsistencies corrected

- The README said 58 migrations. There are 67; the newest is 067, `food_merge`.

## Found and left for a decision

- **Backups are not encrypted.** A shared `.zip` holds lab results and vitals
  in plain form. Encrypting them needs a product decision on passphrases.
- **Some public store methods are only used by tests or by nothing:**
  `InjuryNoteStore.updateDescription` and `updateAffectsTraining`,
  `WorkoutBoutStore.updateEquipmentVariant`, and the
  `ExerciseLibrarySeed.*SourceId` constants. They were kept because they belong
  to the stores' CRUD surface.
- **CI actions are pinned by tag (`@v5`), not by commit SHA.** Pinning by SHA is
  a supply-chain hardening option.
- **The lab CSV import is not one transaction.** If it fails partway, the
  reports already written stay. Importing the file again does not duplicate
  them, and `LabStore.record` cannot be nested in another transaction.
